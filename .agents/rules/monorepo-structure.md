# Monorepo Structure Rule

## Scope

Always active.

## Objective

Keep the Brasaland project organized according to the existing monorepo structure.

## Rules

- Read the relevant folder README before making changes.
- Place public websites in uis/website/.
- Place internal management applications in uis/backoffice/.
- Place backend APIs in services/.
- Place reusable libraries in packages/.
- Do not create duplicate application structures.
- Keep coding assistant rules and skills inside .agents/.
- Keep product agents and their capabilities inside agents/ and skills/.
- Ask the developer before changing the repository structure.
